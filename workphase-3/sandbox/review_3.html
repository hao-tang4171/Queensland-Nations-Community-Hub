Form & Card Build Review 3

This was the bigger task — building the content submission form, the API modules, and the glass-card component. I used Claude to help with the code, but all the design choices and checking were mine.

How this connects to A2

  • I didn't reinvent anything from A2 — same colours, same fonts, same way of laying things out. I just made it work.
  • The glass card builds on the A2 look rather than replacing it. The terracotta and ochre are still doing the heavy lifting, the card just gives them some depth.
  • The submission form is basically the working version of what A2 drew on paper.

What this task adds beyond A2

  • Two forms running in parallel — content submission and the subscription form. I decided to keep both instead of squeezing email into the submission API.
  • A new glass-card component, plus tidied-up form and button styles.
  • Different files now have clearer jobs — one for API requests, one for form data and validation, page-level JS for behaviour.
  • I decided to put Bento Grid on hold until the core stuff was working.

Accessibility and readability

The frosted-glass card looks nice but it can hurt contrast if the background behind it is busy. I checked that the body text still reads clearly on it. I also made sure the status messages under the form actually announce success or failure — not just change colour, which wouldn't help everyone.

Decision

I used AI like a coding helper, not like a designer. I gave it my A2 and A3 design docs and my existing code so what it produced would actually fit the project. The design calls were all mine — splitting the form into two, going with the gradient background and glass cards instead of something more commercial-looking, putting Bento Grid on hold. AI followed where I pointed it; the direction itself was mine.

Issues found during the build

  • Service Worker caching kept showing me old files, so for a while I thought my changes weren't working when they actually were.
  • Styles rendered slightly differently on different pages — same component, but it looked a bit off depending on where you opened it.
  • The gradient background wasn't showing up because the form's container had its own background colour sitting on top of it.
  • Some small mistakes in AI-generated code — wrong file paths, class names that didn't quite match the CSS they were supposed to use.

Cause and how I verified the fixes

The caching one I sorted by clearing the Service Worker and doing a hard refresh. The background problem turned out to be the wrapper — it had its own background colour covering the gradient. I removed that and moved the gradient up to the root element, so nothing could sit on top of it. The inconsistent styles came down to import order between pages, which I made the same everywhere.

For the AI-generated code, I didn't trust any of it on sight. I read every file before saving it, checked each import path by hand, and reloaded the page after every change to see if it actually behaved the way I expected. When something broke, I'd grab a DevTools screenshot and the error, hand it back for the next round of help, then re-test after the fix. That cycle — test, find the problem, fix it, test again — ran several times for some components. Slow, but it meant the final code was something I'd actually looked at and signed off on, not just pasted in and hoped.
